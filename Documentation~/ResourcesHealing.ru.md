# Ресурсы, лечение и воспроизводимые расчёты

## Мана, выносливость и другие ресурсы

Создай `ResourceDefinition` для каждого ресурса, собери их в `ResourceProfile` и назначь профиль компоненту `CombatResources`. Профиль содержит до 32 уникальных ресурсов. SO задаёт ёмкость, начальную долю, скорость восстановления и задержку после расхода. Числа копируются при `Configure`; изменение SO не меняет уже созданное состояние.

`MaximumStat` позволяет взять ёмкость из `CombatStats`. После смены экипировки вызови `RefreshMaximums()`: по умолчанию рост ёмкости не восстанавливает ресурс, уменьшение обрезает избыток. `RefreshMaximums(true)` сохраняет долю заполнения. Если хотя бы один необходимый стат отсутствует или некорректен, ёмкости не меняются.

`TrySpend(costs)` суммирует повторные строки, проверяет достаточность всех ресурсов и затем списывает их вместе. Невалидная строка или нехватка любого ресурса отменяет всё действие. Подписчик `Changed` видит уже завершённое списание всех ресурсов. Повторная мутация из этого обработчика отклоняется; реакции следует выполнять после завершения уведомления.

`Restore` возвращает фактически восстановленное количество. `Advance(delta)` учитывает часть шага, оставшуюся после задержки, без покадрового округления. Для ручной симуляции отключи `AutomaticAdvance`. Выключение компонента приостанавливает ресурс; включение не пополняет его. Для нового спавна вызови `ResetResources()`.

## Лечение

`HealingDefinition` содержит 1–8 слагаемых. Доступны фиксированное значение, стат источника, доля текущего/максимального/недостающего HP и доля результата вызвавшего лечение удара. Процент записывается долей: `0.05` означает 5%.

`TryPrepare(source, target, out info, trigger)` создаёт запрос. Затем `target.ApplyHealing(info)` возвращает `HealingResult`. Лечение не воскрешает; запрет лечения и входящий множитель задаются в `HealthDefinition`. Исходящий множитель и необязательный крит задаются в рецепте лечения. Общий лимит срабатывает после обоих множителей и крита.

Поля результата:

- `AppliedAmount` — фактически восстановленные HP.
- `ShieldRestored` — избыток, отправленный в существующий щит.
- `Discarded` — оставшийся избыток.
- `Rejection` — причина отказа.

`Overheal = RestoreShield` выбирает слой по индексу в профиле защиты. Он пополняет существующую ёмкость и не создаёт новый щит. При неверном индексе или выборе слоя без щита избыток отбрасывается. Резисты к урону не уменьшают лечение.

Для вампиризма `TriggeringHealthDamage` берёт только реально потерянное здоровье без overkill. `TriggeringHitIncludingShield` также включает поглощение щитом. Например, удар снял 20 HP и 30 щита: 10% дадут 2 или 5 лечения соответственно.

Старый `Health.Heal(amount)` сохранён и использует тот же путь, включая запрет и входящий множитель. `Health.Healed` сообщает результат принятого запроса, а `Changed` по-прежнему вызывается только при изменении HP. Исключение подписчика логируется, но не прерывает остальные уведомления.

## RNG и время

`CombatExecutionScope` позволяет временно подменить RNG и часы для расчётов. `SeededCombatRandom` задаёт воспроизводимую последовательность; Unity Random.state не изменяется. Все броски урона, критов, шансов статусов, уклонения и блока используют `CombatRandom.Value`. `ManualCombatClock` используется журналом и cooldown эмиттера.

```csharp
var clock = new ManualCombatClock();
using (new CombatExecutionScope(new SeededCombatRandom(42), clock))
{
    emitter.TryFire(origin, direction);
    clock.Advance(1);
    // Таймеры статусов/снарядов/ресурсов двигаются их явными Advance/Simulate API.
}
```

Области действия применяются на главном потоке и закрываются в обратном порядке. Это инструмент воспроизводимых расчётов, а не обещание детерминированности Unity Physics на разных платформах. Подмена часов сама по себе не останавливает Unity Update: ручную симуляцию запускай в контролируемом окружении, отключая автоматическое продвижение соответствующих компонентов.
