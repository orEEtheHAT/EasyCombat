# Телега, посылки и замедляющие области (0.2.0)

В меню **EasyCombat → Delivery → Create Cart Kit** создай набор в новой папке `Assets/EasyCombatDelivery/CartKit`. Изменяются только новые ассеты. Текущая сцена остаётся открыта. Перетащи **LoadedCart** в сцену над коллайдером дороги: внутри один Rigidbody телеги, четыре WheelCollider с отдельной прочностью и посылка с независимым Rigidbody. Телегу и посылку объединяет неподвижный корень; при движении управляй Rigidbody телеги, не перемещай этот корень. Набор даёт физические механики, не ввод/управление транспортом или правила доставки.

| Задача | Что назначить | Поведение |
|---|---|---|
| Износ колеса | Health + ImpactDurability, профиль WheelWear, WheelContactSource | Износ только у колеса, передавшего удар. Обычная опорная нагрузка не наносит урон. |
| Выпавшая посылка | Parcel, профиль FragileParcel. В LoadedCart ссылка SafeHold уже назначена. | Пока центр тела внутри BoxCollider багажника, удар игнорируется. Выход ничего не отнимает. Следующее столкновение выше порога идёт в Health. |
| Грязь | MudVolume — статический триггер с MovementSurface; RollingResistance на колёсах | Учитывается поверхность у фактического контакта каждого колеса. Никакого торможения предметов просто по пересечению кузова. |
| Пушка | ConeTurret, владелец с CombatTeam. На противнике Collider, Health, MovementInfluences, NavMeshSpeedAdapter | Пока противник в секторе, скорость ограничена. Выход, поворот пушки, выключение или остановка освобождают только её вклад. Щиты и HP не меняются. |
| Враг | NavMeshEnemy на запечённом NavMesh | AI задаёт маршрут и базовую скорость через NavMeshSpeedAdapter.BaseSpeed. Компонент поддерживает множитель скорости, не управляет выбором пути. |

**Полигон.** Импортируй sample Delivery Test Route и вызови EasyCombat → Delivery → Create Test Route. Открой созданную DeliveryRoute.unity и нажми Play. Кнопки управляют тягой и тормозом, сбрасывают посылку, переключают луч, направление и скорость патруля. Числа показывают живое HP каждого колеса, груза и текущий лимит скорости врага. В проекте фабрики полигон уже собран рядом с LoadedCart.prefab.

**Урон.** ImpactDamageDefinition задаёт единицу измерения, SafeThreshold, кривую от *превышения* порога, потолок урона, тип и задержку повторов на один приёмник/жизнь. По умолчанию источник — окружение, учитываются обычные правила Health, резисты, щиты и журнал. Игровая реакция на поломку колеса подключается к Health.Died. У каждого колеса собственный Health; HP телеги автоматически не уменьшается.

- **NormalSpeed** (м/с): RigidbodyImpactSource получает нормальную составляющую относительной скорости при начале контакта. Из нескольких контактов одного сообщения берётся максимум.
- **NormalImpulse** (Н·с): проекция суммарного импульса пары на нормаль. При выбранном OwnCollider неоднозначные смешанные контакты пропускаются. Для отдельных физических колёс используй датчик на их Rigidbody или фильтр коллайдера на общем Rigidbody.
- **DropHeight** (м): высота от верхней зафиксированной точки до приземления относительно направления гравитации. На опорном контакте высота сбрасывается, вертикальная стена не считается полом. Выбирай один режим для одного удара: высота и скорость по умолчанию не суммируются.
- **SuspensionLoad** (Н): WheelContactSource выбирает импульс нагрузки своего WheelCollider по росту и пику сообщаемой контактной силы сверх статической опоры (sprungMass × |gravity|). Первый отсчёт задаёт базу. Рост и плато/спад дают одно измерение; параметры нужно калибровать под массу и подвеску. Это перепад нагрузки, не интеграл силы по времени.
- Для собственной рейкаст-подвески передай измерение в `ImpactDurability.TryImpact(measure, magnitude, point, normal, center, out result)`. Возврат true означает отправленный запрос, а не гарантированную потерю HP. Обычные контакты: настрой SurfaceLayers; для защиты при перевозке укажи SafeHold. Защита багажника действует на физические удары этого компонента, не на боевые атаки.

**Грязь.** Множитель SpeedMultiplier адресован моторным контроллерам (персонажи/агенты). Для свободного Rigidbody используется отдельная RollingDeceleration (м/с² при полной опоре). Каждое колесо прикладывает силу против движения в касательной плоскости контакта; LoadShare — его доля массы, для четырёх равных колёс по 0.25. Сопротивление в перекрывающихся объёмах берётся по максимуму. Широкая телега может погрузить в грязь только левые колёса. В воздухе сил нет. Для WheelCollider контакт поставляет WheelContactSource; для других подвесок доступен ApplyGroundContact или луч UseRayProbe с GroundMask, исключающей собственную телегу. Выбирай только один источник на колесо за шаг. VolumeMask должен находить объёмы грязи; насыщение буфера из 32 коллайдеров видно в SaturatedProbes, поэтому удобно выделить грязь в отдельный слой.

**Постоянный конус.** SO AreaTriggerDefinition с Area.Shape=Cone, Duration=0, атаки Enter/Stay/Exit пустые. MovementField начинает работу автоматически или через Fire()/Cease(). Зона использует CombatAreaTrigger.Contact; отсечение направлением, слоями, командами и видимостью выполняет датчик. Настраивай TargetMask для игровых врагов. В базовой политике Enemies значит «не союзник», поэтому назначай CombatTeam врагам и владельцу и исключай нейтральных через слой. Выход обнаруживается на следующей выборке геометрии, не по таймеру Slow. Пересечение нескольких источников использует **наиболее сильное замедление**, без накопления каждые Stay. Временный статус от обычного выстрела продолжает работать самостоятельно. Если назначен MovementSpeedStat, его множитель применяется один раз поверх пространственного. Поля и контакты временные: сбрасываются при загрузке снимка; логика игры заново запускает нужные пушки. Для прямоугольной зоны персонажа используй MovementSurface на одном включённом trigger Collider; Unity должна выдавать физические события для пары (Rigidbody/мотор персонажа).

**FPS.** Установи EasyMovement + ECM2, импортируй sample **EasyMovement FPS Adapter** и вызови **EasyCombat → Delivery → Create EasyMovement Combat Player**. Он создаст локальный CombatFPS из установленного FP_Player_Sample, сохранив связи ввода, камер и шагов. Публичный пакет содержит только интеграционный код. Для собственного префаба нужен CombatFirstPersonController на месте FirstPersonCharacterController и MovementInfluences на той же сущности. Базовые настройки походок остаются в EasyMovement. Применяется `base.GetMaxSpeed() × Multiplier`; минимальная аналоговая скорость получает тот же множитель. Для статуса Slow назначь тот же ключ MovementSpeed, что использует статус. Отключи старый CharacterStatusModifiers на этом же FPS-игроке, если он тоже меняет скорости, иначе ходьба получит множитель дважды. Для NPC EasyMovement.NavMeshFootstepSource может продолжить обслуживать шаги.

**Проверка в сцене.** Сравни колесо, попавшее на уступ, с остальными; выведи посылку за пределы багажника без удара, затем урони на дорогу. На NavMesh дай врагу базовую скорость 6: в конусе ×0.5 станет 3, при смене базовой скорости на 8 под лучом — 4, после выхода — 8. На игроке тот же MudVolume уменьшает скорость ходьбы, спринта, приседания и пользовательских режимов. Обновление поля не пишет новое значение в SO персонажа.

## Проверка версии

Unity 6000.3.22f1, проект фабрики, ноябрь 2026: 346 EditMode и 140 PlayMode тестов прошли без пропусков. Это включает optional FPS/Physics2D и локальную проверку созданной сцены. Тесты проверяют реальные столкновения, отдельные пики нагрузки колёс, границу багажника, перекрытия областей, пересчёт после смены скорости AI и ходьбу/спринт/приседание/пользовательский режим/полёт EasyMovement. Минимальный проект без сторонних ассетов собрал Delivery Test Route в WebGL Development (отчёт Unity: 37 210 010 байт, без сжатия). Это проверка сборки, не замер FPS, не тест на мобильном устройстве или модерации Яндекса.
