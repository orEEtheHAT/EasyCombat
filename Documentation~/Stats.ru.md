# Характеристики и модификаторы

`CombatStatDefinition` — ключ характеристики: например, скорость, сила или множитель урона. `CombatStatsDefinition` хранит базовые значения; `CombatStats` на персонаже хранит локальные значения и активные модификаторы. Локальное значение перекрывает профиль. Ключ без базового значения считается отсутствующим: формула не должна незаметно заменить ошибку настройки нулём.

Порядок расчёта:

`max(0, база + сумма Flat) × max(0, 1 + сумма AdditivePercent) × произведение Multiply × множитель статусов`.

Например: база 100, Flat +20, два бонуса AdditivePercent +0.25 и Multiply 2 дают 360. У AdditivePercent 0.2 означает +20%; у Multiply 1.2 означает ×1.2. Порядок добавления не меняет порядок стадий. Отрицательная база после плоских штрафов и суммарный процент ниже -100% ограничиваются нулём. Переполнение возвращает `false` из `TryGetValue`, а не повреждает формулу.

Создай **EasyCombat → Stats → Modifier Set**, добавь строки и передай SO в `stats.TryAdd(definition, owner, out handle)`. Все строки копируются в состояние этого персонажа одним действием. Если хотя бы одна строка некорректна или превышен бюджет, весь набор отклоняется. Изменение исходного SO не меняет уже применённый набор.

`handle.Remove()` снимает только конкретное применение; повторный вызов безопасен. `stats.RemoveSource(owner)` снимает модификаторы конкретного объекта-владельца по ссылочному равенству. Это удобно для экипировки, аур и пассивных способностей. `null` не является командой удалить всё. Для сброса при возврате персонажа в пул есть `ClearModifiers()`; обычное выключение объекта сохраняет состояние.

`TryExplain` возвращает базу, плоскую прибавку, сумму процентов, множитель и итог для интерфейса/отладки. Чтение после прогрева не создаёт managed-аллокаций. Добавление может расширить заранее выделенный список; общий лимит по умолчанию — 256 строк на персонажа.

Назначение ключа само по себе не меняет движение или максимум здоровья: его читает соответствующий адаптер или формула. Уже существующие формулы `SourceStat` используют итоговое значение `CombatStats` и сохраняют его в снимке выстрела/стака. Разделение ключа и потребителя позволяет одной системе работать в шутере, RPG и стратегии.
