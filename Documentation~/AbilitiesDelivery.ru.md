# Способности и длительные атаки

## Способности

`CombatAbilities` хранит до 32 разных `AbilityDefinition`, их кулдауны и заряды. В каждый момент у персонажа может идти одна подготовка каста. Статические SO не содержат таймеров персонажей.

В SO выбери цель: Direction, Point, Unit или Self. Для Unit настраиваются команды, self, разрешение Downed/Dead; дальность и LOS проверяются до подготовки и повторно при выпуске. Идентификатор жизни защищает от попадания в новый объект, переиспользованный из пула. `FollowTargetDuringCast` определяет, поворачивается ли прицел за целью; замороженный прицел не позволяет обойти реальную дальность или LOS.

`TryActivate(definition, worldPoint, targetHealth)` запускает подготовку. Перегрузка с `out AbilityRejection` объясняет отказ. `Cancel()` отменяет разрешённую добровольную подготовку; `Interrupt()` принудительно прерывает её. По умолчанию запрет Cast прерывает подготовку. Смерть, выключение компонента, Reset/Restore владельца отменяют её. Если InterruptWhenCastBlocked выключен, промежуточный запрет не отменяет ожидание, но в момент выпуска Cast всё равно должен быть разрешён.

Стоимость списывается **при выпуске** одним атомарным платежом. До этого повторно проверяются цель, ресурсы и действия. Отмена подготовки бесплатна. После платежа резервируются кулдаун, глобальный кулдаун и заряд; затем выполняются действия. Реакции на нанесённый урон ждут конца всей способности. Событие списания ресурсов приходит после действий и видит завершённый результат. Уже нанесённый урон не откатывается, если последующее пользовательское действие завершилось ошибкой; в таком случае приходит Failed. Пользовательский `CanExecute` должен быть чистой проверкой, без RNG и изменения игры.

`MaximumCharges=0` отключает ограничение зарядов, сохраняя кулдауны. При положительном числе заряды восстанавливаются последовательно через `ChargeRecovery`. `GetAbility` и `GlobalCooldownRemaining` дают состояние для UI. Большой ручной шаг учитывает остаток времени после выпуска, а не растягивает новый кулдаун. `Advance(dt)` позволяет ручную симуляцию; автоматический общий scheduler обслуживает только активные таймеры.

Действия:

- `AbilityAttackAction` использует существующий AttackDefinition: луч, снаряд, AOE либо прямой пакет в выбранную цель. Для AOE можно выбрать точку прицеливания или дуло. RPM оружия здесь не используется — частоту задаёт способность. Крит и сила бросаются при выпуске.
- `AbilityEffectAction` переиспользует действие реакций: лечение, статус, комбинацию, восстановление ресурса, защитный слой, импульс. Цель — выбранный Health или владелец. Исходного попадания нет, поэтому hit-relative/lifesteal базы равны нулю. Игровые ограничения самого эффекта сохраняются: например, обычное лечение не поднимает мёртвого.
- `AbilityMeleeAction` начинает CombatMelee на владельце.
- `AbilityBeamAction` начинает CombatBeam на владельце. Отмена windup относится к подготовке; уже запущенный луч останавливается через CombatBeam.Stop или своими правилами прерывания. Нельзя запустить две melee/beam-доставки одного компонента в одном наборе действий.

Для снарядов назначь `Pool`, для огненных луж — `AreaPool`; отсутствие доставки проверяется до платежа. Immediate pulse луча и стоимость способности проверяются вместе. Дальнейшие тики луча оплачиваются по отдельности. Эффекты могут быть неуспешны по игровым причинам (иммунитет, полное HP и т. п.) — это обычный выполненный каст, а не повод автоматически возвращать ресурсы.

## Ближний бой

`MeleeDefinition` задаёт пакет Attack, длительность, до восьми непересекающихся временных окон в секундах, радиус, маски и политику повторных попаданий. Геометрия Delivery/Area/ImpactArea самого Attack для melee не используется.

`CombatMelee` читает до восьми Transform-точек вдоль оружия; пустой список использует собственный Transform. `OwnerRoot` укажи на персонажа, чтобы исключить его коллайдеры. `Begin` фиксирует силу/крит один раз. `Advance` проверяет сферический объём вдоль перемещения каждой точки между двумя отсчётами, обрезанного активным окном. Это непрерывная проверка линейного сегмента; большую вращательную дугу анимации нужно подавать более частыми отсчётами или несколькими точками. Историческую траекторию между неизвестными отсчётами система не восстанавливает.

Все точки разделяют память целей: несколько коллайдеров/частей не умножают урон. Repeat выбирает OncePerSwing, OncePerWindow или Interval. Interval допускает один новый контакт при следующем отсчёте после интервала, без задним числом придуманных ударов. Отказ по иммунитету тоже занимает контакт. `TargetMemory` ограничивает число запомненных целей; переполнение видно в `RejectedByMemory`.

`StopSweepAtWorld` прекращает текущий отрезок на стене. `InterruptWhenAttackBlocked` останавливает взмах при запрете Attack. `Stop`, `Impacted`, `Ended` доступны анимации и визуалу. Источник, его новая жизнь и контакты также проверяются при возврате объектов из пула.

## Непрерывный луч

`BeamDefinition` использует hitscan Attack, включая ширину, пробивание и взрыв/лужу при контакте. Duration/Interval определяют тики. PulseImmediately даёт дополнительный тик в момент старта; последующие тики выполняются на кратных Interval отметках, включая конец, если он совпал. Поэтому при расчёте ровного DPS обычно выключают PulseImmediately.

`DamagePerSecond` умножает числовой/формульный пакет на Interval. Вероятности статусов остаются **на один тик**, а не в секунду. По умолчанию сила и крит захватываются при Begin; RerollEachPulse бросает заново на каждом тике. Прицел берётся из текущего Muzzle. `Pulsed` содержит начало, фактический конец и радиус луча для визуала.

PulseCosts списываются атомарно перед каждым тиком; неоплаченный тик не наносит урон и завершает луч. Максимум восемь догоняющих тиков за один Advance; остаток сохраняется, его можно досчитать следующим шагом, в том числе Advance(0). Beam заканчивается после обработки всех положенных тиков. Stop и запрет Cast останавливают его; новая жизнь источника не продолжает старый луч.

Способности, melee и beam не требуют ECM2, Input System или анимационного контроллера. Ввод и анимация вызывают публичные методы; EasyFeedbacks подписывается на события представления.

## Вход, пребывание и выход из области

`CombatAreaTrigger` использует `AreaTriggerDefinition`: общую геометрию Area, отдельные EnterAttack/StayAttack/ExitAttack и интервал пребывания. Любой пакет может отсутствовать — события Contact всё равно доступны. Область определяет состав участников на каждом отсчёте: вход и выход между двумя неизвестными позициями она не восстанавливает. Для быстрого пролёта нужен swept projectile/melee либо более частое обновление.

Enter наносится один раз новой жизни участника; Stay — по интервалу с максимумом восемь догоняющих тиков за Advance на участника; Exit — при следующем отсчёте вне области. Последний применяется как прямой пакет к прежней зоне, без повторной дальности и falloff. Новая жизнь/уничтоженный участник старый Exit-урон не получает. При выходе Contact сохраняет снимок идентификатора участника, даже если объект уже уничтожен.

Duration = 0 означает работу до Stop; положительное время завершается после догоняющих тиков. EmitExitOnStop управляет выходными пакетами/событиями при остановке. StopWithSource завершает область при потере/смерти/новой жизни источника. MaximumOccupants ограничивает память, RejectedOccupants показывает отклонённые входы. Уходящие участники освобождают место перед регистрацией новых.

Это отдельный сенсор зон для аур/ловушек. Обычные огненные лужи с арбитражем пересечений продолжают использовать DamageArea + AreaPulseDefinition + AreaOverlapGroupDefinition. CombatAreaTrigger не участвует в арбитраже таких луж; пересекающиеся сенсоры действуют независимо.
