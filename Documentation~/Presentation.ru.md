# Звук, VFX и числа урона

`CombatPresentationRelay` подписывается на **локальные** события Health, StatusController, DamageEmitter, CombatAbilities, CombatMelee, CombatBeam и DamageArea на своём объекте. Один `CombatPresentationHub` на сцену принимает события, буферизует их и выдаёт `Emitted` в LateUpdate. Ссылку на Hub назначь в инспекторе, через `Configure(hub)` после добавления компонентов или расположи Hub на родительском объекте. Глобальный поиск для каждого попадания не используется. Для DamageEmitter2D есть отдельный `CombatPresentationRelay2D`; события Health в 2D обслуживает обычный relay.

Событие содержит тип, идентичности источника и жизни цели, мировые координаты, направление, число объединённых событий, Amount, крит и исходный SO. Damage — реально потерянные HP, Shield — поглощённый урон, Healing — восстановленные HP + щит. Impact — контакт доставки, Shot — выстрел, AreaStarted/Ended — жизненный цикл лужи. StatusApplied включает добавление/обновление/замену стака; StatusRemoved — снятие. StatusTick отключён у relay по умолчанию: урон тика уже создаёт Damage. События способности включают начало, выполнение и отмену/ошибку. За точными причинами обращайся к исходным событиям, за историей урона — к CombatJournal.

1. Создай SO `EasyCombat/Presentation/Output Rules` и назначь Hub.
2. Добавь relay к актёрам и к префабам луж/доставки, которым нужны эффекты. Hub не создаёт UI или звуки самостоятельно.
3. Подпиши вывод чисел на `hub.Emitted`. Используй `Position`, `Amount`, `Critical`, `Count`. Пули/числа/VFX следует брать из своих пулов.
4. Для EasyFeedbacks импортируй одноимённый sample и добавь `PresentationFeedbacks` рядом с Hub. В Bindings выбери событие и FeedbackPreset, при необходимости SO-фильтр и CriticalOnly. `MinimumInterval` ограничивает проигрывание **одного binding для всех целей**; например 0.03 с не даст одному звуку играть сотни раз за кадр. `ReferenceAmount` задаёт интенсивность amount/reference в пределах 0.1–3; 0 означает постоянную 1. После изменения Bindings кодом вызови Rebind().

Старый `HealthFeedbacks` остаётся для простых сцен. Если используется новый bridge, убери дублирующие старые подписки на те же эффекты. Пакет не включает аудио, VFX или код EasyFeedbacks и не требует его в Runtime.

## Правила и бюджеты

Ключ: тип события + жизнь цели + SO + крит + жизнь источника при SeparateSources. Обычное и критическое попадания не смешиваются. Без SeparateSources разные источники объединяются, Source становится пустым, чтобы не приписывать сумму одному стрелку. Количество и сумма ограничены диапазоном int/float.

MergeWindow > 0 накапливает события до конца первого окна, задерживая только визуальный вывод. Окно не продлевается новыми попаданиями. MaximumPerSecond — фиксированное секундное окно на ключ; GlobalMaximumPerSecond — общее. Ноль отключает соответствующий лимит. MaximumPerFrame ограничивает число вызовов Emitted; Capacity и RateKeyCapacity ограничивают память. Переполнение/превышение частоты отбрасывает **представление**, не игровой результат; счётчики доступны в Hub.Buffer и инспекторе. Вывод не гарантирует исходный порядок: очередь удаляет элементы обменом с последним.

Неуказанные Kind включены без индивидуального лимита и объединения. При Configure профиль копируется; изменение SO не изменит уже работающий буфер. Правило DiscardAfterRespawn отбрасывает старые числа при изменении жизни цели. У Death оно выключено: эффект остаётся на сохранённой позиции. У уничтоженного объекта позиция тоже сохранена. EasyFeedbacks bridge использует WorldPosition без follow, поэтому эффект не переезжает на новое тело из пула.

Hub по умолчанию работает по unscaledTime. Отключение компонента и загрузка combat snapshot очищают очередь. События представления не сохраняются. Исключения наблюдателей логируются и не прерывают остальных наблюдателей/доставку; новые элементы из Emitted ждут следующего Flush. В обработчиках вывода не меняй боевое состояние: это намеренно отдельный слой, на который геймплей не должен опираться.

Буфер использует заранее выделенные массивы/словари. Тест проверяет 0 managed allocations на прогретом submit/merge/flush и локальном damage relay; это не обещание нулевой стоимости пользовательского UI, EasyFeedbacks, рендера или первого прогрева.
