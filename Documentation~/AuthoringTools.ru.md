# Инструменты автора

Все окна доступны в **EasyCombat → Tools** и на второй панели Combat Studio.

## Калькулятор боя

Создай `CombatScenarioDefinition`, назначь Attack и Health цели, затем открой **Battle Calculator**. Дополнительно можно задать здоровье/характеристики/ресурсы источника и цели, начальные статусы, реакции и модификаторы урона. Shots/ShotInterval задают расписание прямых попаданий, ObserveSeconds — окно наблюдения, StepSeconds — шаг симуляции. ShotInterval **заменяет RPM** для данного опыта. HurtboxMultiplier моделирует масштаб зоны, AttackFromBehind — направление относительно секторного блока.

Калькулятор применяет настоящие runtime-правила Health, защиты, статусов и реакций. Основная атака поступает прямо в одну цель: дальность полёта, точность прицеливания, окна анимации и доставка основного оружия здесь не моделируются. Геометрические реакции используют отдельную preview PhysicsScene с двумя участниками. Объекты открытой сцены и её глобальный журнал не получают эти попадания. Определения не изменяются.

Результат показывает реально потерянное HP, поглощённый щит, броню/блок, вклад сопротивления, предотвращение смертью/минимумом HP, перенаправление, overkill, время смерти и график HP/щита. Одинаковый seed воспроизводит последовательность; один прогон не является математическим средним всех случайных исходов. Для сравнения вариантов меняй настройки/seed и сохраняй SO-сценарии.

Бюджеты одного опыта: 1000 ударов, 100000 шагов/разрешённых попаданий и примерно 2,5 секунды вычислительного цикла. Достигнутый бюджет явно помечает результат частичным. Журнал и график ограничены примерно 2048 записями. Если к концу окна остаются догоняющие тики статусов, окно сообщает об этом: уменьши шаг или продли наблюдение.

Пользовательские эффекты/защитные слои/действия отключены по умолчанию. AllowCustomBehaviors разрешает их при условии, что они соблюдают контракт локальных участников и используют EasyCombat-запросы физики; произвольный пользовательский код может обращаться к внешней сцене. Базовые реакции пакета проверены на изоляцию. В PlayMode калькулятор не запускается.

Для собственных синхронных симуляций `CombatExecutionScope` принимает RNG, clock, isolateGlobalEvents и PhysicsScene. Вложенные scope наследуют контекст, Dispose возвращает предыдущий. Подмена физики действует во время вызова, а не навсегда на запущенный снаряд; при ручной симуляции нескольких миров оборачивай каждый Advance соответствующим scope. Physics2D имеет собственные адаптеры и не использует этот 3D PhysicsScene.

## Шаблоны

**Recipe Templates** создаёт новую папку для каждой сборки SO. Повторный запуск не перезаписывает прежний вариант. Общие типы находятся в `Common/DamageTypes` внутри выбранной папки — оружие и сопротивления разных шаблонов используют одни ключи. Если в игре уже есть Fire/Poison/Physical, замени ссылки на свои типы: одинаковое название не делает два SO одним типом.

| Шаблон | Что создаётся / что добавить на актор |
|---|---|
| MixedFirePoisonWeapon | 2–4 огнём + 7–9 ядом, шанс отдельного поджога. Назначить в DamageEmitter |
| FireballAndGround | Взрыв, поджог, временная лужа, группа пересечений OnePerTarget, заменяемые префабы. Нужны ProjectilePool и DamageAreaPool |
| ShieldedEnemy | HP, броня, восстанавливающийся щит, сопротивление огню и уязвимость к яду. Назначить в Health |
| MeleeAbility | Пакет удара, окно взмаха, способность и stamina-профиль. Нужны CombatAbilities, CombatResources, CombatMelee и точки клинка |
| FreezeBuildup | Накопление льда → временная заморозка. Нужны CombatBuildup и StatusController |
| Lifesteal | 10% фактической потери HP, до 32 проков за одну резолюцию. Назначить в CombatReactions |
| PoisonCombination | Ядовитое оружие, три стака → один короткий сильный статус. Реакция на источнике, StatusController на цели |
| BossBodyPart | Здоровье тела/части, передача доли урона и пакет разрушения. Нужен CombatBodyPart с назначенным Core |

Это исходные схемы для настройки, а не окончательный баланс игры. Огненный визуал — простые собственные примитивы, которые можно заменить моделями, партиклами и EasyFeedbacks.

## Диагностика SO

**Definition Diagnostics** проверяет выбранный корень с зависимостями либо всю библиотеку. Показывает потерянные ссылки, нарушения параметров и циклы с путём по определениям. Цикл ссылки отмечается как предупреждение: он может быть намеренным, а лимиты runtime-реакций работают отдельно. Для членов цикла и зависимых от них рецептов рекурсивная проверка IsValid пропускается, чтобы диагностический инструмент сам не ушёл в рекурсию. Калькулятор циклический сценарий отклоняет.

Граф обходит до 4096 объектов/16384 ссылок без рекурсивного обхода стека. При превышении бюджетов отчёт обозначается неполным. Инструмент ничего автоматически не удаляет и не переназначает.

## Объяснение текущего состояния

**Runtime Explanation** подписывается только на выбранный Health. Здесь можно увидеть:

- HP, щиты, состояние жизни, неуязвимость и текущие значения защитных слоёв;
- итоговое сопротивление выбранному типу, включая модификаторы статусов;
- полную формулу выбранной характеристики: база, flat, additive %, multipliers и статусы;
- ресурсы, отдельные таймеры статусов, захваченную силу первого стака, догоняющие тики;
- заряды/кулдауны способностей и значения buildup;
- последнее попадание по каналам и слоям защиты, причину отказа и происхождение действия.

Окно не наносит урон и не изменяет настройки. Для полного исторического журнала используй CombatJournal и вкладку «Журнал» в Studio. «Документация» открывает папку локального руководства и работает также при установке через Git Package Manager.
